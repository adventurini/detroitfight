# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marketing site for Detroit Fight Company, a combat sports gym in Winter Springs, FL. Hand-written static HTML deployed on Vercel from `main` (repo: `adventurini/detroitfight`, live at https://detroitfight.com).

There is no build step, no package manager, no dependencies, no tests, and no linter. Every page is a single self-contained `.html` file with its CSS in an inline `<style>` block and its JS in a `<script>` block before `</body>`.

## Local development

```powershell
powershell -File .dev-server.ps1   # serves the repo root at http://127.0.0.1:3000/
```

The dev server is a ~40-line `HttpListener` that maps URL path → file on disk. It does **not** emulate Vercel's `cleanUrls`, so extensionless links in the markup 404 locally — browse `/boxing.html`, not `/boxing`. Only the root `/` is special-cased to `index.html`.

Deploy = push to `main`. There is no staging environment.

## Architecture: duplication is the design

Each page independently repeats the CSS reset, `:root` design tokens, nav markup, mobile-nav toggle script, footer, and analytics snippet. The content pages are 1,200–1,950 lines each and are ~70% shared boilerplate.

**Any change to shared chrome must be applied to every page by hand.** That includes: nav links, footer, design tokens, GA snippet, and the scroll/mobile-menu scripts. Grep for the pattern across `*.html` and edit each hit — there is no partial/include mechanism to reach for, and introducing a build step is a much larger change than the site currently warrants.

Design tokens live in a per-page `:root`: `--deep-black #0A0A0A` (page bg), `--black #1A1A1A` (cards), `--green #7D9B76` (accent/CTA), `--white`, `--grey #D8D8D8`. Type is Bebas Neue (headings, uppercase, letter-spaced) and Barlow Condensed (body, 400 and 700), self hosted: three latin subset `woff2` files in `/fonts`, declared by inline `@font-face` rules and two `preload` links repeated in every page's `<head>`. Nothing loads from Google Fonts. Right after the three `@font-face` rules every page declares two fallback families, `Bebas Neue Fallback` and `Barlow Condensed Fallback`: local system fonts (Arial and its stand ins) with `size-adjust`, `ascent-override` and `descent-override` set so text is as wide and sits on the same baseline as the web font. They follow the web font in `--font-heading` and `--font-body`, so text takes the same lines before and after the web font arrives and nothing on the page moves (Cumulative Layout Shift). The numbers were measured against these exact font files; a changed font needs them measured again. `h1` to `h4` carry `text-transform: uppercase` for the same reason: Bebas Neue draws lower case letters as capitals, the fallback does not, and the widths only match in capitals. Do not remove either. `vercel.json` caches `/fonts/*` for a year as immutable, so a changed font needs a new file name. Note `thank-you.html` uses stale variable *names* from an earlier red palette (`--red`, `--gold`) that are now assigned green values — don't "fix" the values to match the names.

## Portuguese pages (/pt)

Thirty one pages have a Brazilian Portuguese twin in `/pt` (added November 25, 2026): every content page, the city pages, the guides, the two coach pages and the two legal pages. The list that counts is `PAGES` in the build script. Same file names, so `/pricing` pairs with `/pt/pricing` and `/` with `/pt`. The Portuguese legal pages open with a line saying they are a courtesy translation and the English version controls; keep that line. On a Portuguese page a link to a page with no twin goes to the English page.

**Never edit a file in `/pt` by hand.** The pages are written by `.github/scripts/build_pt.py` from the English page plus `.github/i18n/pt.json` (English string to Portuguese string). It is a helper, not a deploy step: its output is committed and Vercel serves plain files as before. `.vercelignore` keeps `.github` off the site.

After any change to an English page that has a twin:

1. `python3 .github/scripts/build_pt.py`
2. If it prints strings with no Portuguese entry, add them to `pt.json` and run it again. Inline tags inside a string show as `{1}...{/1}` and a line break as `{br}`; the Portuguese string must carry the same ones. `--list page.html` prints a page's strings.
3. Commit the English page, `pt.json` and the rebuilt `/pt` page in the same pull request. `--check` fails when a `/pt` page is out of date.

Script text on `free-trial.html` (button labels, the booked message, alerts) is swapped by the exact match list `SCRIPT_PATCHES` in the build script. Changing that script on the English page stops the build until the matching entry is updated.

## Speed: nothing on the first screen fades in

`.fade-in` starts at `opacity: 0` and is revealed by the `IntersectionObserver` in the script before `</body>`. Chrome does not count hidden text toward Largest Contentful Paint, so a hero that fades in makes Google time the small nav logo instead of the headline (home page phone LCP read 8.6 s in PageSpeed on November 25, 2026 for this reason). The hero blocks (`.hero-content` on `index.html`, `.sub-hero` on the other pages, `.pl-hero-inner` on `private-lessons.html`) therefore carry no `fade-in`. Keep `fade-in` off anything that shows on the first screen of a phone; it is fine further down the page.

## SEO surface

This site was built to be read by search engines and AI crawlers, and several files must stay in sync when content changes:

- `sitemap.xml` — manual list of the extensionless canonical URLs with `lastmod`, the `/pt` pages included.
- `robots.txt` — explicitly allows GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-Web, PerplexityBot, Google-Extended.
- `llms.txt` — plain-language summary of location, programs, pricing, and key URLs for LLM consumers.
- Per-page `<head>`: canonical, Open Graph, and Twitter card tags.
- Per-page inline JSON-LD: the business as `SportsActivityLocation` with `"@id": "https://detroitfight.com/#business"` on every content page (same type and same `telephone` format everywhere), plus `Service` + `BreadcrumbList` + `FAQPage` on program pages, `FAQPage` on `index`, `Person` on `coaches`. Every visible FAQ answer has a matching `FAQPage` entry; edit both.

## IndexNow (automatic, Bing side)

`.github/workflows/indexnow.yml` runs after every successful Vercel production deploy and submits the changed page URLs to IndexNow (Bing, which feeds ChatGPT and Copilot search) via `.github/scripts/indexnow.py`. It covers the pages at the repo root and in `/pt`. The key file `<32 hex>.txt` at the repo root is the public IndexNow key; leave it alone, and keep `.vercelignore` excluding `.github`. Google ignores IndexNow and reads `sitemap.xml` on its own schedule, so sitemap `lastmod` still has to be bumped by hand for every changed page; Search Console "Request indexing" stays manual (Google offers no API for it).
